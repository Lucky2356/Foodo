# Стартовый каталог: продукты и рецепты

Стартовые данные лежат в `shared/data` (`products.json`, `recipes.json`, `reference.json`). Новые продукты и рецепты пишутся не в JSON, а в текстовых источниках `scripts/catalog/sources`: их легче читать и проверять. Сборщик проверяет источники и переносит их в `shared/data`.

```sh
python -m scripts.catalog.build --check   # только проверить
python -m scripts.catalog.build           # проверить и записать shared/data
```

Сборка идемпотентна: запись из источника заменяет запись с тем же id. Источники только разбираются как текст, никакой код из них не выполняется.

## Продукты — `sources/products_*.txt`

Одна строка на продукт, поля через `|`:

```
id | Название | категория | Отдел магазина | состояние | базовая единица | съедобная доля | 12 значений | доп. поля
tofu | Тофу | legumes | Молочные продукты и яйца | processed | g | 1 | 121 12.7 7.3 1.9 0.6 0 0 0 0 0.1 0 29 | pkg=300 g; allergens=soy
```

- **id** — латиница, цифры, `_` и `-`. Название продукта не является идентификатором.
- **Категория** — id из `reference.json → categories`. От неё зависят запреты: категория `pork` у свинины исключает её для «Без свинины».
- **Отдел** — из `reference.json → departments`.
- **Состояние:** `raw`, `dry`, `cooked`, `processed`. **Базовая единица:** `g`, `ml` или `pcs`. Для `ml` обязательна плотность, для `pcs` — масса штуки.
- **Съедобная доля** — от 0 до 1, например 0,85 для картофеля в кожуре.
- **12 значений** на 100 г съедобной части по порядку: ккал, белки, жиры, углеводы, клетчатка (г), витамин A (мкг RAE), C (мг), D (мкг), E (мг), B6 (мг), B12 (мкг), фолат (мкг). `N` — значение неизвестно; это не ноль.
- **Доп. поля** через `;`: `piece=40` (масса штуки, г), `dens=1.03` (г/мл), `spoon=tbsp:15,tsp:5,pinch:0.5`, `pkg=500 g` (упаковка), `allergens=gluten,milk`, `contains=wheat_flour` (составные продукты), `known=0` (состав не известен полностью), `purchasable=0` (не покупается, например вода).

Все значения — оценки разработчика, источник `foodo-estimate-2026-10`, статус «не проверено». Энергия хранится как задано, но сборщик сообщает о грубом расхождении с формулой 4/9/4, чтобы ловить опечатки.

## Рецепты — `sources/recipes_*.txt`

```
@ id | Название | категория | приёмы пищи | порции | выход, г | техники | теги режима | контейнер 0/1 | кухня | острота 0–2 | детям 0/1
Описание одной строкой.
- product_id количество единица
# method_id | Название способа | техника через пробел или - | активное время, мин | общее время, мин
1. Шаг.
2. Шаг.
! Совет (необязательно).
```

- **Категория рецепта:** `breakfast`, `soup`, `main`, `salad`, `snack`, `dessert`, `baking`, `drink`.
- **Приёмы пищи:** `breakfast lunch snack dinner`, через пробел.
- **Техники** — `reference.json → techniques`. Они задают уровень готовки.
- **Теги режима** — `reference.json → diet_tags` или `-`.
- **Кухня** — `reference.json → cuisines`.
- **Острота:** 0 — не острое; 1 — умеренно (чеснок, чёрный перец, горчица); 2 — острое (чили, аджика, острый перец).
- **Детям 1** — блюдо подходит детям: без заметной остроты, без алкоголя, без сырой рыбы и мяса, понятный вкус.
- **Единицы ингредиента:** `g ml pcs tbsp tsp pinch`. Единица должна переводиться в базовую единицу продукта. Например, ложки допустимы только при заданном `spoon` у продукта.
- **Способы приготовления:** минимум один, у каждого минимум два шага. Активное время не больше общего. Альтернативный способ (например, мультиварка) — отдельный `#`-блок со своими шагами и временем.

## Теги существующих рецептов — `sources/tags_*.txt`

recipe-id | кухня | острота | детям

# Android-приложение (APK)

Приложение для Android собирается в GitHub Actions и выкладывается в релиз готовым файлом `foodo-X.Y.Z.apk`. Это оболочка вокруг веб-приложения: внутри — та же гостевая версия Foodo, что и на сайте (статическая сборка, встроенная в APK и открываемая во встроенном WebView через Capacitor). Отдельного «нативного» интерфейса нет. Приложение работает без сети и без сервера, данные хранятся на телефоне. Аккаунты и синхронизация в приложении недоступны — они работают на полной версии сайта с сервером.

Требования: Android 7.0 (API 24) и новее, актуальный Android System WebView.

## Установка

1. Откройте на телефоне страницу **Releases** репозитория и скачайте `foodo-X.Y.Z.apk` последней версии.
2. Откройте скачанный файл. Android попросит разрешить установку из этого источника (браузера или файлового менеджера): включите «Разрешить установку из этого источника» — название пункта зависит от телефона. Это разрешение для приложения, которым вы открыли файл, а не для Foodo.
3. Подтвердите установку.

Проверить файл до установки можно на компьютере: контрольная сумма есть в `SHA256SUMS` релиза, происхождение — `gh attestation verify foodo-X.Y.Z.apk -R Lucky2356/Foodo`, отпечаток сертификата подписи указан в описании релиза.

## Обновления

Приложение само проверяет новые версии: при запуске и каждые 6 часов, пока оно открыто. Отключить автоматическую проверку и проверить вручную можно в *Настройки → Обновления приложения*. Если версия новее, вверху экрана появляется сообщение «Доступна версия X» с кнопками «Обновить» и «Позже».

Как это работает:

1. **Проверка.** Анонимный запрос `GET https://api.github.com/repos/Lucky2356/Foodo/releases/latest` (без входа и токенов; GitHub видит только IP-адрес и версию приложения в заголовке `User-Agent`). Ответ больше 2 МБ отбрасывается.
2. **Выбор релиза.** Предлагается только опубликованный релиз (не черновик и не предварительная версия) с тегом `vX.Y.Z` новее установленной версии, в котором ровно один файл `foodo-X.Y.Z.apk` размером от 1 байта до 150 МБ, с контрольной суммой GitHub вида `sha256:<64 символа>` и адресом точно `https://github.com/Lucky2356/Foodo/releases/download/vX.Y.Z/foodo-X.Y.Z.apk`. Иначе обновление не предлагается.
3. **Загрузка.** Только по HTTPS (перенаправления — тоже только на `https://`), в закрытую папку кэша приложения. Загрузка прерывается, если данных больше заявленного размера.
4. **Проверка файла.** Размер и SHA-256 должны совпасть с данными релиза. Затем Android (PackageManager) читает APK: имя пакета должно быть `io.github.lucky2356.foodo`, versionCode — соответствовать тегу и быть больше установленного, сертификат подписи — совпадать с сертификатом установленного приложения. Если хоть одна проверка не прошла, файл удаляется и ничего не устанавливается.
5. **Установка.** Проверенный файл передаётся системному установщику (PackageInstaller); при передаче SHA-256 считается ещё раз. Android всегда показывает своё окно подтверждения и сам ещё раз сверяет подпись.

При первом обновлении Android попросит разрешить Foodo устанавливать приложения («Установка неизвестных приложений»). Приложение объясняет зачем и открывает нужный экран настроек; после возврата установка продолжается. Это разрешение используется только для обновлений Foodo.

Ошибки показываются по-русски: нет сети, GitHub временно ограничил число запросов без входа (HTTP 403/429, обычно на час), файл не прошёл проверку. При любой ошибке проверки установка не начинается.

Обновление ставится поверх старой версии, данные сохраняются (тот же пакет, та же подпись, то же хранилище WebView).

## Данные на телефоне

- Профили, меню, покупки, остатки и привычки хранятся в памяти приложения (IndexedDB внутри WebView) и не передаются на сервер.
- Резервное копирование Android и перенос на новый телефон для приложения отключены (`allowBackup="false"`, правила `data_extraction_rules.xml` исключают все данные): копии данных не попадают в облако Google.
- **Удаление приложения удаляет все данные.** Очистка данных приложения в настройках Android — тоже.
- Чтобы сохранить или перенести данные: *Профиль → Мои данные на этом устройстве → Резервная копия (JSON)*. Android откроет окно «Сохранить», файл можно положить в «Загрузки» или в облачный диск. Восстановление — там же, «Восстановить из файла». Тот же файл подходит для сайта.
- Экспорт меню и покупок в PDF и XLSX тоже сохраняется через окно «Сохранить».

## Безопасность сборки

- Разрешения: только `INTERNET` (проверка обновлений) и `REQUEST_INSTALL_PACKAGES` (установка проверенного обновления). AndroidX добавляет служебное разрешение уровня signature `io.github.lucky2356.foodo.DYNAMIC_RECEIVER_NOT_EXPORTED_PERMISSION`, оно не даёт приложению доступа к чему-либо.
- Только HTTPS: `usesCleartextTraffic="false"` и `network_security_config.xml` (только системные сертификаты). Страницы приложения отдаются Capacitor изнутри процесса с адреса `https://localhost`.
- Снаружи доступна только стартовая активность; получатель результата установки не экспортирован.
- Веб-часть целиком встроена в APK, сторонние скрипты из сети не загружаются. Действует Content-Security-Policy (`script-src 'self'`, `connect-src 'self'`), смешанное содержимое запрещено. Отладка WebView включена только в debug-сборке.
- Service worker в приложении не регистрируется: обновления приходят только как APK.
- Release-сборка минифицируется R8 (правила — `frontend/android/app/proguard-rules.pro`).

## Сборка в GitHub Actions

Workflow **Android** (`.github/workflows/android.yml`):

- на каждый PR с изменениями `frontend/`, `shared/`, `scripts/prices/` или `VERSION` и на push в `main`: веб-сборка `vite build --mode android`, `npx cap sync android`, debug-APK, минифицированный release-APK с публичным debug-ключом, unit-тесты обновления (Gradle `testDebugUnitTest`/`testReleaseUnitTest` и отдельно `javac` + JUnit), проверка манифеста (версия, разрешения, экспортируемые компоненты);
- смоук-тест на эмуляторе Android 14 (x86_64, KVM): установка обоих APK, запуск, ожидание главного экрана, для debug — проверка WebView через DevTools (интерфейс отрисован, мост Capacitor и плагины на месте, service worker не зарегистрирован, версия совпадает с `VERSION`), снимок экрана в артефактах, падение при `FATAL EXCEPTION` приложения.

Подписанный APK собирает только **Release** (`release.yml`, вручную на `main`): он вызывает `android.yml` с `release: true`. Ключ из секретов декодируется во временный файл (`umask 077`), удаляется после сборки и в журнал не выводится; Gradle берёт параметры подписи только из переменных окружения. Схемы подписи v2 и v3. После сборки `apksigner verify --print-certs` проверяет подпись, SHA-256 сертификата сверяется с ключом из секретов и выводится в сводку запуска. APK добавляется в `SHA256SUMS`, получает Sigstore-аттестацию и выкладывается в GitHub Release. Без APK или без правильной подписи релиз не создаётся. Сборки из PR секретов не получают.

Локально (для разработчика, не на компьютере владельца; нужны Node 22, JDK 21 и Android SDK 36):

```sh
cd frontend
npm ci
npm run build:android                 # vite build --mode android + cap sync android
cd android
./gradlew assembleDebug testDebugUnitTest
scripts/run-unit-tests.sh             # unit-тесты обновления без Android SDK (javac + JUnit)
```

Версии: Capacitor 8.5.3, Android Gradle Plugin 8.13.0, Gradle 8.14.3, compileSdk/targetSdk 36, minSdk 24, JDK 21.

## Версии

- `versionName` — содержимое файла `VERSION` (X.Y.Z).
- `versionCode = X·10000 + Y·100 + Z`, например 0.1.0 → 100, 1.2.3 → 10203. Номер только растёт, поэтому Y и Z должны быть меньше 100 (сборка это проверяет).
- Тег релиза `vX.Y.Z`, файл `foodo-X.Y.Z.apk`. Приложение принимает обновление, только если versionCode файла равен номеру из тега и больше установленного.

## Ключ подписи

Android устанавливает обновление поверх приложения, только если оно подписано тем же ключом. Поэтому ключ создаётся один раз и хранится только в секретах репозитория GitHub.

Одноразовая настройка:

1. Fine-grained token: только репозиторий `Lucky2356/Foodo`, разрешение **Secrets: Read and write**, срок 7 дней.
2. Секрет репозитория `SIGNING_SETUP_TOKEN` с этим токеном.
3. *Actions → Android signing key → Run workflow* на `main`. Workflow создаёт ключ RSA 4096 (PKCS12, 30 лет) и сохраняет секреты `ANDROID_KEYSTORE_BASE64`, `ANDROID_KEYSTORE_PASSWORD`, `ANDROID_KEY_ALIAS`. Пароль генерируется случайно и не попадает в журнал. Публичный отпечаток сертификата выводится в сводке запуска.
4. После успешного запуска удалить секрет `SIGNING_SETUP_TOKEN` и сам токен в настройках GitHub.

Повторный запуск откажется заменять существующий ключ.

### Если ключ потерян или скомпрометирован

Секреты GitHub нельзя прочитать обратно, а другой копии ключа нет. Если секреты удалены или ключ нужно заменить:

1. Удалить старые секреты, создать новый ключ тем же workflow *Android signing key* и выпустить новую версию.
2. Установленные приложения **не примут** обновление с новым ключом: встроенная проверка обновлений покажет «файл не прошёл проверку», Android тоже откажет. Пользователям нужно сохранить резервную копию (JSON), удалить старое приложение, установить новое из Releases и восстановить данные из файла.
3. В описании релиза указать новый отпечаток сертификата и эти шаги.

Схема подписи v3 допускает ротацию ключа, но только пока старый ключ доступен; без него остаётся путь из пункта 2.
